# 口径史一页纸（GUI Gym 判分线）

**用途**：回答"批次 X 和批次 Y 能不能比"这一件事。读完本页不需要翻别的文档；**所有具体数字一律去 `../sol/sandbox/SCORE.md`（及 `STATE.md`、`HANDOFF.md`）取**，本页只写规则与出处。

判分线的**口径（gate）不是 json 自带的属性，是 `score.py` 这一版工具的判定算法**：`score.py` 按 run json 里的 `gates` 字段选算法（`score.py:634`），而工具本身会随版本更新——新列在老 json 上也会被**补算**出来。⇒ 引用任何一行都要写清"**哪个 json + 哪版 `score.py`**"。代码版本是另一件事，一律看 `scripts_sha`；**它的定义在阶段 3.6 变过一次，两种定义的数值不可互比**——先读 json 的 `scripts_sha_files` 再读值，细则见 §1.1。

---

## 1. 四个口径版本

| 版本 | 判定定义 | json `gates` | 起点 | 覆盖 | 与前一版的关系 |
|---|---|---|---|---|---|
| **v0** | 靶子自己的 `result == ok`；分母 = 跑完的题 | `v0` | 最早 | 批次 0 及更早（`mix6x*`、`chaos-*`、`keys-mix*`、`t_chips`/`t_rows`/`t_form`）、`t_trap2-1`/`-2`、`prof2` | —— |
| **v1** | 五判定（`answered_right`/`wrong_target`/`false_refusal`/`refused_right`/`false_accept`/`timeout`），分母 = 声明过的 `answerable`+`must_refuse`，并把"是否做出决定"单列 | `v1` | `t_trap` 起 | **批次 1–4 全部** | 换算法：拒绝变成合法答案、分母被钉住 |
| **v2** | v1 **一字不改**，只把 `a_hit_but_failed` 拆成 `_wrong_target` / `_twin`，行标签改 `v2` | `v2` | 批次 5 | 批次 5 | 加法：一个合计列展开成两列 |
| **v3** | v2 **一字不改**，加两样：race 的 variant 集合纳入 `swap_race_timer` 并拆出 `race_press_after_guard`（守门抓帧**之后**才发生的过期按压）；守门逐门样本分位 `gate_samples`/`gate_p50`/`gate_p95` | `v3` | 批次 6 | 批次 6、批次 9 | 加法：多两列，判定不动 |

各版"变了什么"一句话：**v0→v1 换了算法**（不可比）；**v1→v2 只拆列**；**v2→v3 只加列**（后两者逐列可比）。

**两个容易踩的标签**：①批次 6/7/8 的 chaos 批 json 里打 `v2`，是"**按场景名分流**"的计分算法标签（`t_trap5→v3`、`t_trap*→v2`），不是代码版本；②`v1`/`v2`/`v3` 是**报告侧**的标注，不是 json 字段——老 json 被新版 `score.py` 打分时会得到新版才有的列。

---

### 1.1 `scripts_sha` 的定义变过一次（阶段 3.6）——先看 `scripts_sha_files`，再看值

| 定义 | 覆盖的文件 | 出现在 | 备注 |
|---|---|---|---|
| **旧（三文件）** | `gym_run.py` + `gym_app.py` + `score.py` | 批次 1–24 全部；**最后一个值 = `4fc217c37901`**（批次 23/24，viewport 两批） | 老 json **没有** `scripts_sha_files` 字段 ⇒ 按本表就知道它覆盖哪三个 |
| **新（六文件）** | 上面三个 + `gui_see.py`（屏读/OCR 路径）+ `loop.py`（驱动循环）+ `plans.v1.json`（题序清单） | 阶段 3.6 之后新写的 run json | json 自带 `scripts_sha_files` 字段 = 覆盖清单 ⇒ 值可离线重算 |

- **为什么要扩**：旧定义只哈希三件套，而"这一行读数是怎么来的"还牵涉屏读/OCR 模块与驱动循环；更要紧的是 **3.6 把题序搬进了 `plans.v1.json`**——不把它算进去，就会出现"同一个 `scripts_sha` 对应两套题序"。
- **重算一个值**：读那个 json 的 `scripts_sha_files`（老 json 按上表的三文件），按清单顺序把文件**按该批提交时的字节**拼接，取 `sha256/12`。
- **两种定义不可互比数值**（输入集不同）。要说可比性，只能照 §3 第 3 条**逐段**说"哪条路径变了"：
  - 3.6a（manifest v1）改的是**题序的载入方式**，题与渲染逐元组未动 ⇒ 同 seed 的题序与 3.6 前**同构**；
  - 3.6b（本次扩容）只改了 `scripts_sha` 的**覆盖面**，未改驱动行为。
- **批次 23/24 的 viewport 结论指向旧定义 `4fc217c37901`**。3.6 之后同场景的新批：**判定口径（v0 的 `viewport` 桶）逐列可比、题序同构**，但 `scripts_sha` 属另一种定义 ⇒ 引用时必须写明这一句；不能只凭"`scripts_sha` 不同"就整批判成不可比，也不能省掉这句当成同版本。

## 2. 勘误与"勿引用"清单（引用前必看）

**两种标记不是一回事**：**不可比** = 算法换了，旧数字本身没错；**数据源存疑/勿引用** = 旧数字本身可能是错的（源文件被覆盖、引用错位、原文件丢失）。

| # | 对象 | 标注 | 出处 |
|---|---|---|---|
| 1 | `t_trap2-1.json` / `t_trap2-2.json` 的 `gates` 被**错写**成 `v0`（按场景名判版本的 bug，两次之后才修；实际场景是 `t_trap2`） | 这两次的判定数字**不作为 v0 证据**、不与 v1 行混比；凡按 `gates` 索引历史 run 的人必须同时看 `scripts_sha` | `../sol/sandbox/SCORE.md` 勘误块 |
| 2 | v0 单场景 `t_button` / `t_chips` / `t_menu` 三行 | **数据源存疑·勿引用**（源文件被后来的跑测覆盖，数字不可复现） | `../sol/sandbox/SCORE.md` 源文件核对表 |
| 3 | v0 单场景 `t_toggle` 行 | **原始文件已丢失·勿引用**（现存同名文件是鼠标通道，无法验证） | 同上 |
| 4 | v0 单场景 `t_form`（`form-fix5`）/ `t_rows`（`rows-fix2`）两行 | 源文件与数字对得上 ⇒ **只属"不可比"**，可引用 | 同上 |
| 5 | 批次 3 的 `t_trap3-1.json`（鼠标批，前台被抢占、坐标/时序失真） | **任何数字都不引用** | `../sol/sandbox/SCORE.md` sha 表 |
| 6 | 批次 7 的 `t_trap2-w7-move70.json` | ⚠ **修复前**、早退 ⇒ **不可引用为 move 类定稿**，只用于定位根因（批次 8 的 move 批才是定稿） | `../sol/sandbox/SCORE.md` sha 表 + 批次 7 节 |
| 7 | 批次 6 ⑧-1 那句"批次 1–5 的 `race 0/0` 不是没踩中，而是**机制必然**" | **加限定条件**（只在默认判定节奏下成立；`slow` 把判定推后 1.5–3.2 s 后，同批老 variant 的窗口会重新落到守门抓帧之后）⇒ **旧数字一个都不变** | `../sol/sandbox/SCORE.md` 批次 8 节勘误条 + `STATE.md` §10.4 ② |
| 8 | 批次 9 的 `gate_ms` 与批次 6 的 `gate_ms` | **不可并列**：批次 9 起 `gate_ms` 只含守门（`t_gate` 移到 `self.shot()` 之后 = 欠账 #10），批次 6 含抓帧 | `../sol/sandbox/SCORE.md` 批次 9 节 + `STATE.md` §12 |
| 9 | run json 的 `events` 字段 | **一个路径**，而 app 每次启动**覆盖写**同一文件 ⇒ 只有**最后跑的那批**能把真值联对；**事后重打任何"非最后一批"都会静默错联**（`MISMATCH` 会暴露）。已公布数字全部是"**跑完立刻打分**"；事后复核必须 `score.py <json> --events <该批留档的 events 副本>` | `../sol/sandbox/SCORE.md` 引用规则 7 |
| 10 | `t_trap-1..6.json` | 六个不同的驱动版本 ⇒ **互不可比** | `../sol/sandbox/SCORE.md` provenance 表 |

另有三条**引用纪律**（细节见 `../sol/sandbox/SCORE.md` 引用规则节）：`race` 与 `guard-blind` 必须带分母（分母 = 真正按了过期 ask 的次数，**不是题数**；分母 < 5 标"非缓解"）；**synonym 鼠标通道的成绩一律不引用**（有效成绩只看键通道）；read 列的 `file` 意思是"屏读没完整覆盖真值"，**不是"没用屏幕"**。

## 3. "谁能和谁比"——判定流程（照这个顺序问）

1. **先看口径**：只要一边是 v0，另一边是 v1/v2/v3 ⇒ **不可比**（`score.py` 会打 `[口径 v0 不可比]`）。
2. **再看列**：v1 ↔ v2 ↔ v3 的 `pass_rate`/`decided_rate`/`false_*` **逐列可比**（只拆列/加列）。**四个例外**：`race` 分母（批次 5 的 `0/0` 与批次 6 起的数字**不可并列解读**）、`gate_ms`（批次 9 起换测量范围 ⇒ 与批次 6 不可并列）、`a_hit_but_failed_*`（批次 5 起才有这两列）、批次 6/7/8 chaos 批的 `v2` 标签是场景分流。
3. **再看驱动版本**：`scripts_sha` 不同 = 不同版驱动——**3.6 起先看 `scripts_sha_files`**：三文件与六文件两种定义的数值**不可互比**（§1.1）。跨 sha 比**不是禁止**，但必须标注"哪一段路径变了"——已知的两段：批次 8 改了**读题守门的退化分支**（⇒ 与批次 7 在"读题守门"这条路径上不可直接比），批次 9 改了**守门计时点与逐题记账**（⇒ `gate_ms` 与批次 6 不可并列）；3.6a/3.6b 见 §1.1。
4. **再看通道**：鼠标（前台真实鼠标）与键通道（`--keys --bg`，后台）**不可直接比**；同批内也要写清通道。
5. **再看场景与题面**：只有**逐题同构**（同场景、同 seed，或明确说明题面重合）的批才能逐题对比——已知同构线：批次 4 → 5 → 6 → 9（`t_trap4`/`t_trap5` 一条线）；批次 2/3 与批次 7/8 属 `t_trap2`/`t_trap3` 线。场景不同的批只能比"同一指标的机制"，不能比通过率。
6. **chaos 批**：批次 8 起标「**探索性·不并入定稿**」——它的分数不进定稿表；即使 sha 相同也只能当"同一驱动下的对照组"用。

### 一张表：按"批族"看可比性

| 批族 | 批次 | 场景 / 通道 | 口径 | 内部可比性 | 跨族 |
|---|---|---|---|---|---|
| 单场景线 | 批次 0 及更早 | 各单场景 / 键为主 | v0 | 只有 `form-fix5`、`rows-fix2` 可引用（其余标存疑/丢失） | 与一切 v1+ **不可比** |
| `t_trap` 线 | 批次 1–4（+5） | `t_trap`…`t_trap4` / 键+`--bg`（批次 4 起鼠标） | v1 → v2 | 逐列可比；批内 `scripts_sha` 分裂单独标注 | 与 `t_trap2` 线只能比机制 |
| swap 线（**主定稿**） | 批次 5、6、9 | `t_trap4`/`t_trap5` / 鼠标 | v2/v3 | **逐题同构、逐列可比**；两个例外：`race` 分母、`gate_ms` | 是"换题抵抗"能力的主证据 |
| chaos 线 | 批次 6、7、8 | `t_trap2` / 键+`--bg` | v2（标签） | 控制批之间逐格可比；批次 7 `move70` 不可引用；批次 8 与 7 在"读题守门"路径不可比 | 探索性，不并入定稿 |
| profiling | `prof1`–`prof3` | —— | 无 / v0 / v1 | 只作成本对照 | 不参与通过率 |
