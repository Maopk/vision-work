## 1. 引言

**本章回答**：为什么需要一个"行为可审计"的 GUI 智能体评测，而不是又一个成功率榜单。

GUI 自动化领域已经有大量基准在问"能不能点对"。它们共享一个读数习惯：把一整轮交互压缩成一个成功率，或者再加一个步数。这在**只关心结果**的场合是够用的，但当我们关心的是一个智能体**在干扰下是否仍然守住指令**时，单个数字会立刻暴露三处信息损失。

**其一，同一个分数混装了不同的行为。** 一个智能体点对了目标，和一个智能体**该拒答时拒答了**，在成功率里可能都是"通过"；反过来，点了错目标和**不该拒答却拒答了**都可能都是"不通过"。这两组行为的工程含义完全不同：前者是感知或匹配的缺陷，后者是策略或阈值的问题。把它们压成一列，等于放弃了归因能力。

**其二，读数无法回答"这是谁的错"。** 一条测量线的读数取决于测量工具本身。本项目的历史里，最刺眼的几条结论不是关于被测方的，而是关于**测量工具**的：驱动的读题重读在干扰下退化后，旧代码把"读不出"当成"问题变了"，于是不按、重规划，最后死锁；守门的计时点把抓帧时间算进去了，于是跨批的耗时不可比；重规划换记录时丢了逐题字段，于是聚合看着对、明细对不上；抓帧返回空位图时整批直接退出，于是已经跑完的题一行不留。这些都不是被测方变笨了，而是**读数被工具污染**了。一个不可审计的评测会把它们全部记在被测方账上。

**其三，不可比的数字会静默地传播。** 判定算法换过一版（v0 → v1：拒绝从"失败"变成合法答案，分母从"跑完的题"变成"声明过的题"）；之后两次只是拆列与加列（v1 → v2 → v3）。后者逐列可比，前者不可比。如果引用者不知道这件事，把两个版本的数字并排放进一张表，错误就已经发生了——而且没有任何机制会报警。

### 我们做了什么

本项目建设了一条**可复核的测量线**，由三个不同源的部件组成：

- **靶子**（`../sol/sandbox/gym_app.py`）：一个自建的桌面 GUI 练习靶，自己生成题表、自己写状态文件、自己按真值判分。它同时是可注入干扰的载体：可以在运行中改变布局、延迟判定、弹出干扰窗、重掷题面。
- **驱动**（`../sol/sandbox/gym_run.py`）：一个**全盲**的 GUI 智能体——它只通过常驻执行器（actor，本地端口 `:8731`）抓帧、发键、点鼠标，**从不读靶子的状态文件**。真值不下发到任何决策路径，这是本项目的硬规则（`STATE.md` §0）。
- **评分器**（`../sol/sandbox/score.py`）：在跑完**之后**把靶子的真值与运行记录联结起来，输出分类判定、分母、分位与引用所需的元数据。

围绕这三件套，本线建立了一套**可以被审计的读数结构**，本文把它概括为三个贡献：

1. **五判定口径与分母纪律。** 判定被拆成六类（`answered_right` / `wrong_target` / `false_refusal` / `refused_right` / `false_accept` / `timeout`），并额外单列"是否做出了决定"；分母只收**声明过**的题（answerable + must_refuse）。拒绝由此变成一个可以"拒得对"的合法答案，而不是沉默。口径被版本化，每一批的 json 与 `score.py` 版本、`scripts_sha` 一起入表。
2. **affordance-first 的感知策略。** 驱动先确定"画面上哪些块是**画出来的控件**"，再读它的标签，最后才决定动作；而不是先读一遍文本、再猜哪一处可点。它带来两个直接后果：同词双现（同一词既出现在标题里也出现在按钮上）可以被唯一化，而"读到但读不准"可以被识别为测量问题而不是能力问题。
3. **可证伪迭代。** 每一次改代码之前，先把**假设、证伪条件、观测点、判据**四行写进存档；跑批之后逐条核对判据；估算在实测之后一律作废重写；失败的批次与探索性的批次同样留档，并显式标注"不可引用"或"不并入定稿"。

### 范围与不做什么

本文覆盖批次 1–16：其定稿线（换题抵抗为主证据的一条逐题同构线）、探索性的干扰线（四类干扰 × 两个强度）、两次**已回退的能力修复尝试**（批次 14；以及只有 2 题干跑、未成批的批次 15）、**一次跑成并保留为定稿的修复**（批次 16，16 题前台窄批，仍未覆盖 `--bg` 鼠标通道），以及三组**只读探针**——它们不改代码、不裂 `scripts_sha`，只回答"这条欠账还在不在"。

明确**不做**的事：不评价具体模型的强弱（本线的被测方是驱动，不是模型选型）；不给绝对能力结论（样本是自建靶、单机、单任务族）；不把探索性批次与探针产物并入定稿表。

**读者指引**：只想知道"两批能不能比"，读 `SCORE-history.md`（一页纸，含四版口径表、勘误清单与判定六步）；想知道"怎么重跑"，读 `HANDOFF.md` §3（一行可复制命令）。

**本章的诚实边界**：本文**只引逐条核对过的外部条目**（第 2 章末给出 11 条与核对口径），不做文献综述；也不主张本线的题目族覆盖了真实桌面软件的全部交互形态——恰恰相反，第 6 章会说明哪些交互（滚轮、拖拽）在本线**至今没有有效覆盖**，以及弹窗这一类**覆盖到哪一步为止、边界在哪里**。

## 2. 相关工作

**本章回答**：这条线与已有的 UI 自动化测试、Agent 评测、拒绝能力研究分别在哪里不同。

**UI 自动化测试。** 这一支的传统目标是把人的操作序列稳定地重放出来，因此核心工程问题是"元素定位"与"动作执行"：如何在下一次运行时仍然找到那个控件、如何让点击落在它身上。以截图本身作为定位原语的 Sikuli 把"元素"从控件树里解放出来，改用屏幕上的一块图像来指认它 [1]；同一批作者随后把这条路推进到 GUI 测试 [2]；而录制回放真正难的地方——时序与触摸的敏感性——在移动平台上被系统地处理过 [3]。本线保留了同样的底层能力（抓帧、OCR、像素结构、输入注入），但把"动作执行"降级为中间量：**判据不是动作有没有发出去，而是行为是否守约**。同一个"点下去"的动作，在"题面被换过"的语境下可能是对的，在"题面没变"的语境下就是错的——传统测试框架不区分这一点，本线的守门（按压前再验一帧）就是为区分它而存在的。

**Agent 评测。** 主流做法是结果导向：给定任务与初始状态，看最终状态是否达成目标，再附上步数或 token 成本——WebArena 用一套可复现的真实网站环境把这件事标准化 [4]，Mind2Web 把"在没见过的网站上完成任务"当作泛化度量 [5]，WebVoyager 把真实网站上的端到端任务与自动评判一起端上来 [6]，桌面侧则有 OSWorld 把同一范式搬到操作系统级任务 [7]。它的优势是可扩展、可自动判分；代价是上面第 1 章说的三处信息损失——而"评测本身可不可信"也已经被公开质疑：有工作系统性复测后认为，此前接近饱和的成功率里有相当一部分来自基准自身的缺陷，而不是能力提升 [8]。本线在结果之外单列两样东西：**是否做出决定**（`decided`），以及**决定落在哪一类**。前者把"超时/未决定"从失败里摘出来，后者让"拒得对"与"点得对"分别可数。

**拒绝能力与不确定性。** 在统计学习里，"允许模型拒答"是一个有几十年历史的选项，其代价与收益已有系统综述 [9]，其中一类做法是给网络加一个可学习的选择性判据 [10]；在对话系统与安全对齐语境里，"拒答"通常作为行为规范讨论，并已被证明与模型内部一个可分离的方向有关 [11]。在自动化语境里它往往被当成失败。本线把它做成一个**声明式题族**：靶子在自己的题表里声明这道题是 answerable 还是 must_refuse，评分器据此在两侧分别计数——`false_refusal`（该做而拒）与 `false_accept`（该拒而做）。这不解决"什么该拒"的规范问题，但它让"拒得对不对"变成可测量的事实。

**干扰鲁棒性测试。** 常见做法是给环境加随机扰动或对抗扰动，再看性能退化。本线的干扰是**可归因注入**：四类干扰（布局移动、判定延迟、弹窗、题面重掷）各自独立、强度可控，而且靶子会把自己的注入事件写进事件文件——于是"干扰到底发生了没有、发生了几次"可以不依赖驱动的自报。更进一步，本线把**失败模式本身当作方法学证据**：批次 7 的干扰批之所以有价值，不是因为它跑出了多低的分数，而是因为它暴露了驱动守门的一处假阳性，并被后续批次修掉且有回归证据。

**本小节没有外部引用**：本报告没有核对到一条专门做"GUI 智能体在可归因干扰下行为退化"的可查文献，因此不引——这条空缺明写在这里，而不是用一句"已有大量研究"带过。

**与本文的差异一句话**：别人问"能不能完成任务"，我们问"在干扰下守住指令了吗、该拒的拒了吗、这个判断本身可信吗"。

## 3. 方法论

**本章回答**：读数是怎么定义的、怎么版本化的、以及怎么防止它被误读。

### 3.1 六类判定与"声明过的分母"

评分器把每一道题的结果落到六类之一：

| 判定 | 含义 | 前提 |
|---|---|---|
| `answered_right` | 做了动作且落在真值目标上 | 该题 answerable |
| `wrong_target` | 做了动作但落在非真值目标上 | 该题 answerable |
| `timeout` | 到预算结束仍未做出决定 | 任意题 |
| `refused_right` | 未做动作，且该题确实应当拒答 | 该题 must_refuse |
| `false_refusal` | 未做动作，但该题本应作答 | 该题 answerable |
| `false_accept` | 做了动作，但该题本应拒答 | 该题 must_refuse |

分母只收**声明过**的题（answerable + must_refuse，`score.py:110-112`）。未经声明的题不进分母——这条规则的实际意义是：靶子偶尔生成的、语义不完整或渲染失败的题不会稀释通过率，它们只会体现在"跑完的题数"与"声明数"的差里。与之配套的是 `decided`：把"没决定"从"决定错了"里摘出来，因为这两者的工程含义不同（前者是时序或预算问题，后者是感知或匹配问题）。

### 3.2 affordance-first：先认块，再读标签

驱动的读题不是"整屏 OCR 之后找关键词"，而是三段：

1. **找画出来的块。** 把一帧切成网格，判定哪些格子是"画上去的"（几乎每个像素都不同于页面底色），再把连通的格子合成候选矩形。控件是**被画出来的**，正文里的词不是——这条先验把"标题里的同名词"和"按钮上的标签"分开了。
2. **读块里的标签。** 只在候选块内部读字，并据此判"这个标签像不像控件标签"。
3. **同词双现的唯一化。** 一个词可能出现多次；只有当它**恰好落在一个画出来的块里**时才算数，否则交给拒答路径。这是同词双现（twin）题族能被修好的机制基础。

同一条策略也用在**按压之前**：驱动在按下之前会再抓一帧，确认"题面还是原来那道题"。如果这一帧读不出来，就回落到便宜的结构指纹（把 banner 区域降采样成格子，数变化格数）而不是直接判"变了"——这正是本线最早的一处测量缺陷（批次 7 的干扰批把"读不出"误判成"变了"，导致不放行、重规划、死锁；批次 8 修掉并加了退化规则，批次 10 又把重读框改成每帧用像素段重算，避免取景框被布局移动甩开）。

**真值不下发**是这条策略的硬约束：驱动没有任何路径可以读到靶子的 `truth` 字段；状态文件只允许评分与诊断使用，且诊断结论不得回流到决策路径（`STATE.md` §0）。

### 3.3 可证伪迭代：四行假设先于改动

本线每一段工作都以四行开头，写进存档之后才允许动代码：

- **假设**：一句话，说清"我认为现在错在哪里、改成什么会好"；
- **证伪条件**：若干条，写成"如果修完还看到 X，就说明假设错了"；
- **观测点**：跑批时要看哪些字段（例如某计数、某分位、某题族逐题结果）；
- **判据**：做到什么算完成（例如某计数归零、某分位涨幅不超过阈值、某题集逐题无翻转）。

跑完立刻按判据逐条核对，结论写回存档；**估算在实测之后一律作废重写**（本线为此留下过若干条"设计时估 X、实测 Y、原估算作废"的记录）。这套流程的直接收益是：任何一次"改完好像好了"都必须落到具体字段上，含糊的改善无法通过。

### 3.4 口径版本与可比性

判定算法是**计分工具的属性**，不是 json 自带的属性——这一点必须写在方法里，因为它违反直觉：同一份运行记录，用新一版的评分器去读，会得到旧版没有的列；反过来，旧 json 的通过率也可能因为算法换了而"变化"。因此本线把口径显式版本化：

- **v0**：靶子自己的 `result == ok`，分母 = 跑完的题。
- **v1**：五判定 + 声明分母 + 单列 `decided`——**换算法，与 v0 不可比**。
- **v2**：v1 定义不变，只把一个合计列拆成两列——**拆列，逐列可比**。
- **v3**：v2 定义不变，把某一类换题竞态的变体集合纳入统计并拆出"守门抓帧之后才发生的过期按压"，另加守门逐门分位——**加列，逐列可比**。

引用任何一行都要写清"**哪个 json + 哪版 `score.py`**"；代码版本是另一件事，看 `scripts_sha`（**阶段 3.6 起 = 六个文件** sha256 的前 12 位：`gym_run.py` / `gym_app.py` / `score.py` / **`gui_see.py`** / **`loop.py`** / **`plans.v1.json`**；批次 1–24 用的是**三文件**定义 ⇒ 两种定义的数值**不可互比**，新 json 自带 `scripts_sha_files` 清单可离线重算，完整规则见 `SCORE-history.md` §1.1）。跨批比较按固定顺序问六个问题：口径 → 列 → 驱动版本 → 通道 → 场景与题面 → 是否探索性批。前五个问题里任何一处不成立，比较就只能比"机制"，不能比通过率（完整规则与批族矩阵见 `SCORE-history.md` §3）。

### 3.5 引用纪律（防误读的硬规则）

本线把最容易误读的几处写成硬规则，违反即不得引用：

1. **带分母**：竞态类与"守门盲判"类的结论必须带分母，分母是"**真正发生了那个竞态的次数**"，不是题数；分母低于 5 只能作机制证据，不能作缓解结论。
2. **通道隔离**：后台键通道与前台鼠标通道的成绩不可直接对比；某类工具接口在后台通道下未经视觉路径的实现，其成绩一律不引用。
3. **折叠归折叠**：形近字折叠只用于**找目标**，判定"题面是否变化"必须用未折叠的原始串——否则会把字形噪声读成变化。
4. **探索性标注**：干扰类批次的分数一律标"探索性·不并入定稿"，且其注入率只引用**每批自己的**事件文件（驱动自报的干扰计数只数其中一类，两者不可互推）。
5. **事件文件的覆盖写**：靶子每次启动会覆盖同一份事件文件，而评分器正是从它读真值的——因此**只有最后跑的那一批**能联对真值，事后复核必须指定该批留档的事件副本。已公布的数字全部是"跑完立刻打分"得到的。
6. **不完整批不并列**：抓帧失败后落盘的**部分批**（带 `partial` 标记、退出码 3）只用来证明"失败路径能落盘、能打分"，不与完整批并列成成绩。

### 3.6 自检与留档

每次跑批之后必须运行评分器的自检（`score.py --selftest`，一组固定的口径断言），并把 `scripts_sha`（阶段 3.6 起覆盖六个文件，见 §3.4）写入批次表。每一批留四件：运行 json、靶子状态、靶子事件、驱动日志。第 5 章的每一次改动都遵循同一套顺序：改一处 → 裂一次 sha → 干跑两题确认首题真的产生了输入 → 正式批 → 立刻打分 → 四件留档 → 入 sha 表。

**本章的诚实边界**：口径版本是工具属性，意味着**历史 json 会被新工具"重新解释"**——引用旧批时必须同时给出当时打分的工具版本，否则读者无法区分"当时是那样"与"用今天的工具看起来是那样"；本线已有若干条"不可比"与"勿引用"的标注，全部列在 `SCORE-history.md` §2。

## 4. 系统

**本章回答**：三件套各自负责什么、它们的边界在哪里（哪些限制是设计选择，哪些是能力缺口）。

### 4.1 靶子：一个会自己变坏的练习场

靶子是一个**单窗口 Tk 应用**，只用标准库。它的职责有三件：

1. **出题。** 题表由种子决定，所以同一 `--seed` 能在不同批次间生成**逐题同构**的题面——这是第 5 章里"唯一支持逐题对比的那条线"的前提。题目分成几类：单按钮、行选择（要翻页时涉及视口）、表单填写、菜单调用、开关与滑块、拖拽装配。此外有三类特殊家族：**同词双现**（同一个词既是标题又是按钮标签）、**换题**（题面中的目标词在两题之间切换，有定时触发与按压后触发两种）、**不可答 / 须拒答**（题面本身声明这道题应当拒答）。
2. **判分。** 靶子自己按真值判分，把结果写进状态文件。注意这是"靶子自己的判定"，与评分器的六类判定是两件事：前者是环境的事实，后者是把事实与驱动行为联系起来之后的分类。
3. **注入干扰。** 四类干扰可在运行中触发：**布局移动**（窗口或内容整体平移，制造"计划时的取景框已经失效"）、**判定延迟**（把判定推后，制造"过期按压"的窗口）、**弹窗**（弹出一个需要被清掉的干扰窗）、**题面重掷**（在运行中改变题面或控件）。干扰的每一次注入都由靶子写进事件文件——这一点很关键：干扰是否真的发生，可以**不依赖驱动的自报**来核对。

靶子侧还修过一处与测量直接相关的缺陷：状态文件用"先写临时文件再原子替换"的方式落盘，而驱动会高频轮询同一个文件，两者相撞时会抛权限错误；由于写状态恰好发生在按键回调的第一行，异常会**吞掉已经收到的按键**，表现为"某些键永远到不了"的假故障。修法是两层：写侧重试并在必要时退化为直接覆写，调用侧把诊断写盘包在异常保护里——**记账绝不允许中断它所在的回调**。

### 4.2 驱动：只看像素、从不看答案

驱动是本线的"被测方"，也是本线最大的工程量所在。它的输入只有一帧帧的屏幕像素（经执行器抓取），输出只有键盘与鼠标动作。它的处理链可以分成三层：

- **文本层**：整屏 OCR 取词与行分组。这一层负责读题面与读控件标签，但它**不单独决定动作**——因为字号小、字形近、背景淡，纯文本路径的假阳性与假阴性都不可接受。
- **结构层**：把一帧降采样成格子，用"几乎每格像素都不同于底色"的判据找出**被画出来的块**，得到候选控件的矩形；再用"banner 区域的暗像素连续行块"定位题面区域。这是 affordance-first 的实现处：**先认块，再读块里的字**。
- **窗口层**：通过执行器做窗口查询与输入注入，包括后台通道下的焦点交接（把键盘焦点交给靶子而不改变前台窗口）。

在这三层之上是**决策与自校验**：

- **读题**：题面区域裁剪 → 放大重读 → 归一化 → 与已知题型模板匹配。对"题面是否变化"这个问题，驱动同时维护一个便宜的结构指纹（格子级变化计数）与一次昂贵的文本重读；两者不一致时的取舍规则是显式的（读不出 ⇒ 回落指纹；读出的文本与期望**没有任何连续两字符以上的公共子串** ⇒ 判为没读到而不是变了）。
- **按压前守门**：真正按下之前再抓一帧，用上述规则确认题面没被换掉。守门本身的开销被单独计量（逐门样本进分位），因为它是"干扰下守住指令"这一主张的**成本侧证据**。
- **回读校验**：填表类题目在写完之后读回，不一致就重来一次；这是被实测教训逼出来的（清空动作与新输入走不同队列，清空晚到会吃掉首字符）。
- **重规划**：一轮动作之后没有等到判定，就重新读屏、重新决策；重规划的次数与原因都进逐题记录——第 5 章会看到，正是这条路径上丢过一个字段。
- **失败路径**：抓帧失败不再让整批退出——有限次重试之后仍失败，就把**已经完成的题**写成一份带标记的部分批（退出码 3），使"批跑一半环境坏了"这件事从"丢光证据"变成"留下证据"。

### 4.3 评分器：在跑完之后联结真值

评分器的定位是**事后**工具：它读取运行 json、靶子的状态与事件文件，把"驱动做了什么"与"真值是什么"联结起来，输出六类判定、分母、`decided`、逐门分位，以及引用所需的元数据（场景、通道、`scripts_sha`、口径版本）。它的三个设计要点：

1. **联结发生在运行之后**，且必须匹配事件文件（见第 3.5 节第 5 条）——驱动在运行时看不到任何真值。
2. **自检内建**：`--selftest` 用一组固定的口径断言锁住语义（例如"一次没被守门看见的过期按压必须被计成守门盲判"），使口径变更无法悄悄发生。
3. **不完整批要自己说话**：读到带部分标记的 json 时，评分器在输出顶部打两行警示，避免它被误当成绩引用。

### 4.4 运行定式与环境铁律

这套系统的运行方式本身是测量条件的一部分：

- 跑批必须**从交互桌面侧启动**，并显式给出正常显示状态。曾经从后台作业启动，靶子窗口被创建在屏幕外的坐标上，抓帧全空，整批白跑——窗口几何不是无关细节。
- **同一时刻只能有一个靶子窗口**（驱动要求目标窗口唯一），因此所有批次串行。
- 正式批之前**先干跑两题**，确认首题真的产生了输入；否则"零按压"这类环境故障会伪装成能力结论。
- 每次跑测前后查前台状态并记录是否被改变：本线的默认约定是训练不抢用户前台，能走后台通道就走后台通道。

**本章的诚实边界**：①文本层受 OCR 限制，**形近字**（如把 `GAMMA` 读成 `GAMMB`）在历史上确实造成过误读，本线不声称消灭了它，只声称**它不会再被误读成"题面变了"**；②结构层与输入注入的能力不对称——后台通道下键盘有显式的焦点交接，鼠标动作没有等价的实现，因此**滚轮与拖拽在当前的后台通道下量不到**（第 6 章 #18）；③窗口层依赖一个常驻执行器进程，它是单点，但它的可用性在每批开工前被显式检查。

### 5.2 四个核心发现

**① `fill` 边界（淡化题面）。** 靶子可以把控件画得很淡，用来测"视觉证据不足时驱动怎么办"。本线在这条边界上得到两个结论：一是**标定必须与受测同批**——早期用合成帧标出的可见度阈值，与真实淡化档对不上，导致该档的判定落在阈值带之外（这条至今是未完成项，见第 6 章）；二是驱动在证据不足时的正确行为是**拒答**，而本线确实观察到了稳定的全拒答档。换句话说，这条边界同时暴露了"驱动的保守性"与"标定的脆弱性"两面。

**② 同词双现（twin）。** 同一个词既作为标题出现、又作为按钮标签出现。按"读完文本、取第一次出现"的朴素实现会系统性失败——这不是随机误差，而是**设计使然**（标题也响应点击，但按标题算错）。修法是把选择权交给结构层：只有**恰好落在一个画出来的块里**的那次出现才算候选。修复后该族从全错变为全对，并留下一条至今有效的结构边界：**标题仍然不可点**，任何"按 OCR 顺序取首个出现"的实现都会全错。

**③ 换题竞态（race）。** 题面会在两种时机被换掉：定时触发与按压后触发。竞态的本质是**顺序**：如果过期按压发生在"守门抓帧"**之后**，那么守门看不见它，按下去就是错的——但这不是驱动不谨慎，而是它的验证与动作之间存在一个不可消除的时间窗。本线为此做了两件事：靶子新增了一个把换题窗口推到这个时间窗之后的题族，驱动新增了一个可调的抖动参数；于是这一类竞态**第一次拿到了非零分母**，并且口径里专门拆出一列"守门抓帧之后才发生的过期按压"。这条发现的方法学意义大于数值意义：**一个为零的计数，可能是"没发生"，也可能是"机制上不可能发生"**——本线曾把前者写成后者，后来在同一条线的另一个强度档上自己推翻了自己（勘误见 `SCORE-history.md` §2）。

**④ `popup` 类干扰：从"不可测"改判为"部分可测"（本报告唯一一处被自己推翻的事实错误）。** 干扰窗弹出后，批次 8 在**后台键通道**下**一次都没清掉它**：弹窗留屏、驱动的按键被它吃掉、题目永不结束且靶子不前进（两档都只 fire 一次就早停）。当时的判断是"这一类在当前通道下不可测，要借鼠标通道已有的视觉路径"。第十段定位到的真根因**不是"看不见"**：执行器回包里那份窗口列表被**折叠截断**（只留前几条），而清障闸门读的正是这一份 ⇒ 按标题找弹窗恒为空 ⇒ 闸门在第一步就 `break`、**一次按键都没发**；改法只是改读未折叠的那一份、再加三个清障计数（**判定路径一字未动**）。批次 12（键通道）与批次 13（键通道，另一个强度档）随后都跑满题数、清障计数逐次全成 ⇒ **键通道两个强度档都成立**。第十一段同时试了**鼠标通道（前台）**：同一条视觉清障路径在那一支上仍然清不掉弹窗（且那一支**没有清障计数**，所以"没看见"与"看见了没点"在数据上不可区分），题目卡在"被弹窗挡住"、三题后早停 ⇒ **鼠标通道下仍不可测，记为一条新欠账**（数值与逐条判据见 `../sol/sandbox/SCORE.md` 批次 12 节与批次 13 节）。**第十三段又往前推了一步**：先做只读探针，把"打不掉"拆成**两道独立**的门——① 那一支读的是**主窗矩形**的抓帧，按钮在这一帧里**从来不是候选**（块检测给 0，文本路径只读到散文里的同一个词、又被否决规则否掉）；② 那一支的点击都带前台请求，而执行器把它解释成"**把主窗钉在最上层**"，于是坐标点对了也落在主窗上。随后按这两条改了一版（读弹窗自己的窗口帧 + 点击不带前台请求 + 修坐标原点）：**方向有效、判据没过**——干跑两题全过、正式批清障 10/11，但第 21 题连续三次失败触发早停，而判据要求"清障次数等于看见次数**且**不早停"⇒ **按该段自己的终止条件整体回退**，驱动回到原 sha，只留下补丁、证据批与三条下一步（同点补点一次／失败时降级用靶子自己绑定的按键／把"单次漏点 ⇒ 整题死锁"的耦合拆开）。所以本版结论与 v0.3 相同：**键通道可测、鼠标通道不可测**；区别只在于"不可测"的机制已经被拆到能指着代码说出来的程度（数值与逐条判据见 `../sol/sandbox/SCORE.md` 批次 14 节与 `STATE.md` §20 / §21）。**第十四段试了第二版**：既然"同点补点"只是对未知原因再赌一次同一条路，就改用靶子自己绑定的那条退路——漏点时**降级发 `Return`**（靶子的弹窗把这个键绑在按钮上）。改动净 +24 行、`py_compile` 与 `selftest 41/0` 都过，但**干跑两题就被证伪**：13 次发现弹窗、**0 次清掉**（`popup_dismissed` 与新计数 `popup_key_dismissed` 两个键在 `stats` 里根本不存在），两题全 `NONE`、退出码 1，A 批与 B 批都没有跑。这次失败给出的**机制结论**比"哪条修法失败"更重要，也把前一版的 10/11 解释清楚了：非 `--bg` 通道里驱动发的按键是**真实前台按键**（Windows 把它交给前台窗口；只有 `--keys --bg` 才带焦点交接），而本机前台会被不断抢回 ⇒ 45 次按键全部落空；鼠标点击则是**按坐标**投递的，弹窗又是 `-topmost` ⇒ 像素命中即可达。所以这一支不是"快修好了"，而是"**只剩按坐标投递这一种机制能到弹窗**"；剩下的选择因此从"再换一种写法"变成**通道层**的三选一：走前台批并显式声明通道／给鼠标动作加上键盘那样的托管输入与焦点交接／接受边界（见 §6.2 D、§7.3 与 `STATE.md` §23）。

## 6. 发现

**本章回答**：在什么条件下会错，以及哪些盲区到今天还没关上。

### 6.1 可引用的结论清单

下列结论都满足"有批次证据 + 口径版本明确 + 边界写清"三条；每条给出**成立的工况**与**出处指针**（数值一律去指针处取）。

1. **换题抵抗在逐题同构的鼠标线上可测且可复现**（成立工况：同场景、同种子、同通道，口径一致）。配套机制解释：竞态是否发生取决于换题窗口与守门抓帧的先后，而与"驱动是否谨慎"无关——因此竞态类结论**必须带分母**。
2. **同词双现可以被结构性修好**（成立工况：词恰好落在唯一一个画出来的块里）。边界：词出现在多个块里、或只出现在标题里时，本线不解（前者返回不确定，后者按设计判错）。
3. **"读不出"与"变了"必须分开**（成立工况：任何带干扰的读题路径）。这条结论的证据是一次典型的死锁：读不出的重读被判成"题面变了"，于是驱动不放行、重规划，题目永不结束。修复引入两条规则（读不出 ⇒ 回落结构指纹；重读文本与期望无足够长的公共子串 ⇒ 判没读到而非变了），并在后续批次里把重读的取景框改为**每帧重算**，使"计划时的框被布局移动甩开"这一类失效不再发生。
4. **单字形改写不会被漏判**（成立工况：后台键通道的该题族）。证据是"结构指纹静默而文本重读仍然抓住"的一次逐题记录：指纹一格未动，驱动仍识别出题面变化并正确作答。据此，本线把原先挂着的一项欠账（"盲判的分母"）**关闭**，理由不是"分母是 0 所以无所谓"，而是"这条路径已经不由指纹负责"。
5. **抓帧失败不再丢批**（成立工况：靶子进程被杀、窗口被最小化两种永久失效）。重试预算耗尽后，已完成的题会写成带标记的部分批并能被评分器照常打分；但**"瞬时"类空帧没有被构造出来**，所以"重试能救回瞬时空帧"既未证实也未证伪。
6. **测量缺陷与能力缺陷必须分开记账**（属于方法结论，也是本报告的核心主张）。本线累计定位到的驱动侧缺陷分两类：**记账类**（计时点含抓帧、逐题字段丢失）与**失败路径类**（空帧零容忍）。两者都会把工具的问题记在被测方账上。

### 6.2 未关的盲区（按族归纳）

盲区清单的完整版有二十三条（`HANDOFF.md` §4，每条带实测证据与代码锚点）；这里按性质归成五族，并逐族给出**对主结论的影响**：

**A. 感知与文本族**——形近字混淆（例如把某个字母读成另一个）；单字形改写的**结构指纹本身不可靠**（变化格数低于阈值）；淡化题的**可见度标定**用的是合成帧，与真实淡化档对不上，导致该档判定落在阈值带之外。影响：**不影响主结论**（换题抵抗的证据由文本重读承担、淡化档的结论本来就写成"该档不可解"），但"淡化边界"这一条至今没有同批标定，属于**未完成的测量**。

**B. 竞态与时序族**——老题族的一类换题在机制上落在守门抓帧**之前**，因此它在历史批次里的"零"**不能**解读成"没有过期按压"；同族还有"按压后换题每题空等到预算结束"的效率问题。影响：**影响解读方式**（这正是"为零的计数不能直接当结论"的来源），但不影响已公布数字本身；本线为此专门加了一列"守门抓帧之后才发生的过期按压"。

**C. 记账与仪器族**——守门耗时一度含抓帧，跨批不可并列；逐题抖动一度只进聚合不进明细，导致明细无法核对；事件文件被覆盖写，事后重打非最后一批会**静默错联真值**；新增的"取景框位移"字段只记每题首次，**证明不了守门那一帧的框被移动过**。影响：前三条**已修**（并有批次证据），第四条是**仪器局限**，只能靠重跑或加字段解决，不影响已有结论（已有结论不依赖该字段）。

**D. 能力缺口族**——`popup` 类在**键通道上已可测**（两个强度档逐次全成；真根因是闸门读到了被执行器**折叠截断**的窗口列表，见 §5.2 ④），**鼠标通道下仍打不掉**（同一条视觉路径一次都没点中、3 题后早停，记为新欠账；第十三段的修复尝试把该支的清障率提到 10/11，但**未过判据、已回退**；第十四段的第二次尝试（漏点时降级发靶子自己绑定的按键）在**干跑两题**上就被证伪（13 次发现、0 次清掉）并回退 —— 两次尝试合起来的机制结论是：该支**只有按坐标投递的点击能到弹窗**，按键要能到必须像键通道那样做焦点交接（属通道层改动），见 §5.2 ④ ⇒ 这一族的状态仍**不变**（第十五段进一步把这一支**定为接受边界**：#20 通道层选 C —— A 要跑必须先重落补丁并先拆耦合、B 改执行器不可核对，见 §5.2 ④、§7.3 与 `STATE.md` §24）；**第十六段把这一族又推进了一格**：按那两个前置条件（重落补丁 + 拆耦合）做完后，**鼠标通道 16 题前台窄批跑满且清障计数与看见次数相等** ⇒ **鼠标通道在窄批（16 题 / 0.70 档）下已可测**，`STATE.md` §7 **#20 收口为"还清"**，驱动改动**保留为定稿**（`gym_run.py 3fa0e4ba4b1b9679`）；**它没有兑现的那部分随即被第十九段补上**——那条拆耦合在 **3 批 × 16 题**前台窄批里**第一次被真实触发并救回**（三批 **0/28 遭遇死锁** ⇒ 95% 单侧上限 ≈ **10.7%**），但"**漏点是否消除**" 仍**【未决】**（**第二十段收口为"不追加"，见 §7.3 第 1 项**；见 §5.2 ④ 末段、`../sol/sandbox/SCORE.md` 批次 16 节 `16.5` 与批次 17–19 节））；后台通道下鼠标动作不生效，因此滚轮与拖拽**至今没有有效覆盖**（历史记录里这两类的条目全部来自更早的口径，不可引用）。影响：**这是本报告最大的边界**——它限制的是"覆盖了哪些交互形态"，而不是"已有结论对不对"。

**E. 环境与几何族**——从后台启动会让靶子窗口出现在屏幕外，抓帧全空；窗口被最小化后对枚举与辅助接口都不可见，而进程仍然活着（"空帧"不等于"靶子死了"）；批次 3 因前台被抢占而**整批不可引用**。影响：**不影响主结论**（这些都是运行条件，且已被运行定式覆盖），但它们解释了为什么"失败批也要留档"是必要的。

### 6.3 盲区是可以被"量到结论"的（三个例子）

本线关闭过三项欠账，三种关闭方式恰好覆盖了三种结局：

- **修好了**（取景框冻结）：先只读量出机制与成本，再改一处、裂一次 sha、跑一批同协议对照 ⇒ 关键计数归零且逐题无翻转 ⇒ 关闭。
- **量到它不存在**（守门盲判的分母）：只读探针跑一批小量，发现该路径已由另一条更可靠的路径承担，分母恒为 0 ⇒ **关闭而不是硬造分母**。
- **把"丢证据"改成"留证据"**（抓帧空帧）：不改判定路径，只加失败路径的出口（重试 + 部分批 + 退出码）⇒ 用两条人为构造的失效证明新出口有效 ⇒ 关闭。

**本章的诚实边界**：①"不影响主结论"这句话在 `STATE.md` §7 里是**逐条**给出的（每条欠账配一句为什么），本节只给归纳；②盲区清单会随批次增长——本章的 23 条是**2026-10-05 收工时刻**的快照，不声称完备；③未被列出的盲区不等于不存在，只等于**尚未量到**。

## 7. 讨论

**本章回答**：这条测量线的意义、局限，以及下一步该往哪里走。

### 7.1 可审计评测的意义

本线最想主张的是一句朴素的话：**读数要能回答"这是谁的错"**。当评测把一个智能体的分数当作它的能力时，测量工具本身的缺陷就被自动记在了被测方账上。本线的做法是把"归因"变成结构性的：判定分类（把该做而没做、做了但做错、该拒而做、拒得对分开）、分母纪律（只统计声明过的题、竞态类必须带分母）、版本纪律（口径版本 + 代码版本双标注）、引用纪律（通道隔离、探索性标注、不完整批不并列）、以及**失败路径要么落盘要么不产分**。

第二个主张是：**"拒答"必须作为协议的一部分被显式建模**。在自动化语境里，不做动作通常等于失败；但只要能区分"该做而拒"与"该拒而做"，拒绝就从一个沉默的失败变成一个可以审计的决定。这一点在本线的题族设计里是声明式的：题表声明这道题是否应当作答，评分器在两侧分别计数。

第三个主张是方法层面的：**跨批比较是一个可以判定的问题**，而不是靠读者自觉。本线把它写成六个按序提问的问题（口径 → 列 → 驱动版本 → 通道 → 场景 → 是否探索性），任何一步不成立，比较就降级为"只比机制"。这条规则救过本线两次（一次是把"机制必然"写得太满，一次是把含抓帧的耗时与扣帧的耗时并排放）。**阶段 3.6** 在这条纪律上又收了一个口子：版本戳不再只覆盖三件套，而是覆盖**屏读 / OCR 路径、驱动循环与题序数据**，并且每个运行记录自带「我哈希了哪些文件」（`scripts_sha_files`）—— 于是「同一个 `scripts_sha` 对应两套题序」这件事**在格式上不再可表达**（§3.4、`SCORE-history.md` §1.1）。

### 7.2 局限

- **单机、单靶、单任务族**：靶子是自建的桌面控件练习场，结论不能外推到真实软件或网页；本线的目标从来不是"评测一个智能体有多强"，而是"把一类行为变成可审计的测量对象"。
- **未做视觉-语言模型混合**：驱动是纯感知管线（OCR + 像素结构 + 执行器），没有接视觉语言模型。这既是选择（便于归因到具体规则）也是局限（感知上限被 OCR 与结构先验锁住）。
- **覆盖有洞**：滚轮与拖拽没有有效覆盖（**第二十三段**：进体系设计已落 `DESIGN-18-scroll-drag.md` §9 —— 靶子两处一行 + `score.py` 必改、新类 `viewport` **单列且不进主分母**）；**阶段 3.4 更新**：**进体系已实施（A 落地）** —— 滚轮 / 拖拽不再是「未声明题」，但它们仍只有**前台真鼠标**路径（`--bg` 鼠标通道不可用，盲区 21），且该桶**不计入五判定与主分母**（首次真取数在 3.5）。**新增缺口 #21**（第二十三段判定、**高优先级、未修**）：鼠标通道徽章判定族的 `must_refuse` 题会被点在 prose 坐标上、题不前进（`STATE.md` §7 #21 + §30）；**第二十四段补**：**重跑清单**（必重跑 2 批、须重评空、**#20 结论不受影响**）与**修复设计**（推荐路线②「点了没反应 ⇒ 走拒答」，+7 净行）见 `STATE.md` §31 与 `DESIGN-21-mouse-operability.md`；`popup` 类**在键通道上两个强度档都可测**，鼠标通道的旧结论是"**不可测**"，**该结论已被第十六段的 16 题前台窄批取代**（见第 6.2 节 D 族与第 5.2 节 ④；本句保留旧表述只为标注它指向的那段历史）。这一处**试过两次修复**：第一次按只读探针拆出的两道门改（清障率从"一次不中"提到 10/11，**未过判据、已回退**），第二次改用靶子自己绑定的按键（**干跑两题即被证伪、已回退**）；两次合起来量出的是**通道性质**——该支只有按坐标投递的点击能到弹窗，按键要能到必须做焦点交接（见 §5.3、§6.2 D 与 `STATE.md` §23）——所以这里的洞是**实测过两次的洞**，而且"再换一种坐标／按键写法"这条路已经被排除。**第十五段把这条洞写成显式边界**（#20 通道层选 C）：欠账保持开着、不再试第三种写法；A（前台批）只在需要真凭据时按需跑，且必须先重落补丁 + 先拆耦合（`STATE.md` §24）。**第十六段按那两个前置条件做完并跑了一次 16 题前台窄批 ⇒ 判据达成、#20 收口为"还清"（窄批口径）** —— 于是这个洞从"鼠标通道不可测"收窄成"**只在窄批（16 题 / 0.70 档）下可测；`--bg` 鼠标通道整条不生效、滚轮与拖拽的连续鼠标交互仍未覆盖**"（见 §5.2 ④ 末段、§5.1 批次 16 行与 `STATE.md` §25）。 —— **第二十二段补**：#19 的四格已齐（`0.35`/`0.70` × 键/鼠标），**#19 关死**；填格的那一批（批次 20）自己 21/24 早停，原因是**一条 `must_refuse` 题在鼠标通道下没走拒答**（新欠账 #21、与弹窗通道无关）；#18（滚轮/拖拽）的实现前提已核查完、推荐零代码改动的前台批（见 `DESIGN-18-scroll-drag.md` §8）。 **阶段 3.5 更新**：#18 从「设计已落」推进到「**部分覆盖**」—— 前台真鼠标通道上两批各 8 题全部跑完（批次 23 `t_rows` / 24 `t_chips`），`viewport` 桶首次真取数且**不进五判定与主分母**；**仍不覆盖** `--bg` 鼠标通道与滚轮 / 拖拽的连续交互公差 ⇒ 这个洞**收窄了、没有封**（`STATE.md` §34.2/§34.6）。**阶段 3.6 更新**：这一段**不改任何覆盖结论** —— 它把题序搬进数据、把版本戳的覆盖面扩到屏读 / 驱动循环 / 题序文件（见 §3.4 与 `SCORE-history.md` §1.1）；上面这条洞（`--bg` 鼠标通道、滚轮 / 拖拽连续交互）**仍是本报告最大的边界**。

### 7.4 方法学教训（可直接复用）

1. **先量再改**：动手前先量机制与成本（本线的一次成本估算在实测后作废重写，实际值比估算低两个数量级）。
2. **先写假设再写代码**：四行（假设 / 证伪条件 / 观测点 / 判据）写在存档里，跑完逐条核对。
3. **失败批是资产**：失败模式说明的是工具与环境的边界；本线最重要的两类修复都是从失败批里读出来的。
4. **环境是测量条件的一部分**：窗口几何、前台状态、启动方式、单实例约束都会改读数，必须写进运行定式并每批记录。
5. **样本窄等于空信息**：分母小的结论只能作机制证据；"为零"必须先问"机制上是否可能发生"。
6. **同一处连续失败两次就停下量原始数据**：本线曾在一处靠"猜阈值 → 跑一次"连崩数轮，改用一次原始像素剖面就同时解出了结构（哪里是题面、哪里是文字行、哪条边有伪影）。

**本章回答**：一句话说清做了什么、证明了什么、还剩什么。 **第二十四段把 B（修 #21）开工前的两件做完**：重跑清单（必重跑 2 批；**#20 结论不受影响**）与修复设计（推荐路线②，+7 净行、不改靶子）。 **第二十三段把剩下的两件各推一格**：#21 **判定为通道级缺口**（高优先级、未修）、#18 的**进体系设计**落盘（`DESIGN-18-scroll-drag.md` §9，`score.py` 必改）。**第二十二段又把这条线收了一格**：`popup` 的四格覆盖面（2 档 × 2 通道）已齐、#19 关死；剩下的两件是 #18（滚轮/拖拽，已有零代码改动的实现方案）与 #21（鼠标通道的拒答路径）。

我们造了一条**可审计的 GUI 行为测量线**：一个可注入干扰的自建靶子、一个只看屏幕像素的全盲驱动、一个事后联结真值的评分器，外加三样纪律——判定分类与分母、口径版本化、引用与留档规则。用这条线，我们**证明了**"在干扰下守住指令（包括正确拒答）"可以被拆成可计数、可复核、可跨批比较的对象；也**证明了**这条线的读数首先取决于测量工具是否诚实——本线在驱动侧定位并修掉了四类判据/测量缺陷（读不出被当成变了、计时点含抓帧、逐题记账丢字段、空帧零容忍），每一类都留下了"改一处、裂一次 sha、跑一批对照"的证据，并关掉了三项欠账（修好一项、量到一项结构性不存在、把一项从丢证据改成留证据）。**还剩**两件事：一是能力缺口（`popup` 类**键通道已可测、鼠标通道仍打不掉**——试过两版：第一版方向有效但判据未过，第二版在干跑两题上即被证伪，两版都已回退——两次把原因收敛成一句"**这一支只有按坐标投递的点击能到弹窗**"；滚轮与拖拽没有有效覆盖。**两处缺口都已在第十五段按 C 写成显式边界**：#20 通道层选"接受边界"（欠账保持开着、A 按需、B 不做），#18 方案选"键通道优先 + 鼠标连续交互记已知边界"（见 §5.2 ④、§7.3、`STATE.md` §24 与 `DESIGN-18-scroll-drag.md` §7）；**第十六段又把 #20 推到了终点**——按 A 的两个前置条件（重落补丁 + 拆耦合）做完后跑 16 题前台窄批，**跑满不早停、清障计数与看见次数相等** ⇒ **判据达成、鼠标通道在窄批下可测、改动保留为定稿**，同时如实记下三件没兑现的（拆耦合未被触发、漏点未复现、单批单档），见 §5.2 ④ 末段与 `STATE.md` §25；**第十九段**又把 #20 的最后一块补上——那条为"漏点"买的保险在 **3 批 × 16 题**前台窄批里**第一次被真实触发并救回**（三批 **0/28 遭遇死锁** ⇒ 95% 单侧上限 ≈ **10.7%**）；**第二十段把 #20 整项收口（结项）** —— "漏点是否消除" =【未决】并判定为"不追加"（代价与收益见 §7.3 第 1 项），口径只写"**路径可达 + 单次有效**"，见 §5.2 ④ 末段与 `../sol/sandbox/SCORE.md` 批次 17–19 节），一类是未完成的测量（淡化档标定、逐题位移字段、个别翻转未做重复批）。这两类都不动摇已有结论，但都写在明面上——因为一条测量线最重要的性质，不是它的数字有多好看，而是**它的边界是可被引用者核对的**。

**第二十六段（#21 修复）**：审计→修复→验证的闭环在这一段完整走了一次 —— 缺陷由**计分口径**（`false_accept`）暴露、根因定位到**代码行**（鼠标分支缺键分支的可操作性判据）、修法是**行为判据**而非像素阈值、验证用**同 seed 同协议的复跑**并逐题回归（唯一翻转 = 那道题本身）。它同时给出一条可复用的纪律：**修复的判据要写成「路径迁移」（该题从 `false_accept` 变 `refused_right`），而不是「指标不得上升」** —— 后者会把正确的行为变化误判成回归。

**阶段 3.4（`viewport` 进体系）**：这一段没有跑批，全部证据是离线的，而它给出的是另一种可复用纪律：**改"含义"与改"结构"不要同批** —— `viewport` 是一个新的真值类（含义），manifest v1 是把题表搬出代码（结构，而其验收判据恰是"题序一字未变"）；同批落地会让两者都不可归因，所以只落 A、把 manifest 留成设计（`../docs/TASK-AUTHORING.md` §5）。同样值得记的是"**等价性用离线回归证明，而不是用一次跑批**"：新旧打分器在 5 个既有 run json 上输出逐字节相同，比"再跑一批看看像不像"更省、也更硬。
**阶段 3.5 的收束**：`viewport` 桶的真取数把欠账 #18 从「设计已落」推到「**部分覆盖**」（只在前台真鼠标通道、两批各 8 题）；同一段里 **v1.0 被声明并冻结** —— 冻结的是**接口**（run json `schema: 1` + 文档 + 引用纪律），不是开发；`(h)` 计数单一化明确不在声明内。数字见 `../sol/sandbox/SCORE.md`；判据、边界与 v1.x 清单见 `STATE.md` §34。
